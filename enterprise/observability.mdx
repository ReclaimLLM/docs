Enterprise observability gives you a cross-developer view of how AI is being used across your entire organization. You see usage by developer, team, model, and project — and when something looks unusual, you can follow the trail from a metric spike all the way to the exact session that caused it. No guesswork, no waiting for a monthly bill with no context behind it.

## Org-wide usage dashboard

The enterprise usage dashboard aggregates captured session data across every developer in your org. It is the starting point for understanding AI usage at scale.

<CardGroup cols={2}>
  <Card title="Usage by developer" icon="user">

  </Card>
  <Card title="Usage by team" icon="users">

  </Card>
  <Card title="Usage by model" icon="microchip-ai">

<Note>
  Cross-developer analytics refresh every **15 minutes**. Dashboard figures may lag up to 15 minutes behind real-time capture activity.
</Note>

## Session drill-down

The dashboard is the entry point, not the destination. Every metric and aggregation links directly to the sessions behind it.

<Steps>
  <Step title="Identify a signal">
    Spot a spike in token usage, an unusual model in the distribution, or a team whose activity has changed sharply. The dashboard surfaces these as time-series charts and ranked lists.
  </Step>
  <Step title="Filter to the relevant context">
    Apply filters by developer, team, model, date range, or project to narrow the view to the activity you want to investigate.
  </Step>
  <Step title="Open the session list">
    Click through from any chart or table row to a filtered session list scoped to that developer, team, or time range.
  </Step>
  <Step title="Inspect the session">
    Open an individual session to see the full interaction — messages, tool calls, file diffs, token counts, and model metadata. For encrypted sessions, admins with decrypt access can open the raw transcript.
  </Step>
</Steps>

## Token usage and efficiency

Navigate to **Enterprise → your org → Tokens** to see a per-project token breakdown with efficiency ratios. This view helps you understand not just how many tokens you're using, but whether that usage is working well.

### Metrics available

| Metric | What it tells you |
|---|---|
| **Tokens per session** | Average token load per agent run or conversation in a project |
| **Tokens per line changed** | How much AI context is consumed relative to actual code output |
| **Cache-hit ratio** | How often the model can serve from prompt cache rather than processing full context |
| **vs. org median** | Each project's metrics compared to the organization-wide median, so you can identify outliers |

<Tip>
  A high tokens-per-line-changed ratio may indicate developers are sending unnecessary context on every request. A low cache-hit ratio may suggest prompt structure optimizations that could meaningfully reduce cost.
</Tip>

## Historical backfill

When a developer joins your organization, their existing captured sessions can be backfilled into the enterprise view. This means your analytics aren't limited to sessions captured after you set up the org — you get a full historical picture from day one.

<Info>
  Backfilled sessions are attributed to your org and the developer's assigned team using the team assignment active at the time of backfill. Historical attribution reflects current team membership, not team membership at the time the session was originally captured.
</Info>

## How RCLM extends your existing visibility

If your developers already use Claude Code or other AI coding assistants, you may have some usage metrics available through those tools. ReclaimLLM adds the layers that standalone tool metrics cannot provide on their own.

| Layer | What you get |
|---|---|
| **Per-tool metrics** | Sessions, tokens, and activity data scoped to a single tool or provider |
| **RCLM cross-tool capture** | Unifies Claude Code, browser sessions, local API proxy (`rclm-proxy`) traffic, and hosted Enterprise Gateway calls into one org view |
| **RCLM session detail** | Every metric spike links to the underlying session — not just a number but the actual interaction |
| **RCLM governance workflows** | Retention enforcement, sensitive session review, scoped access, and export controls tied to captured content |

<Note>
  Individual tool metrics tell you what happened in aggregate. RCLM adds the full session record so any alert or anomaly can be traced all the way back to the exact interaction that triggered it.
</Note>
